pocket.01 / THE PROBLEM

Bitcoin capital needs everyday uses.

Mezo lets Bitcoin holders borrow MUSD. New users still need a simple way to turn that money into a payment, a request or productive savings.

Access

Wallet setup and unfamiliar transaction steps make the first payment harder than it should be.

Use

Borrowed MUSD needs useful destinations: other people, merchants and Savings.

Confidence

Users need a clear recipient, amount and confirmation before trusting a money app.

Pocket brings Mezo's money into familiar payment flows.01 / 08
pocket.02 / THE SOLUTION

Pocket. Send. Request. Get paid.

A mobile web app with social sign-in and a Privy embedded wallet. Users keep MUSD in their own wallet and send directly to a username or address.

Sign in

X, Telegram or email. An embedded wallet is created and synced to a Pocket profile.

Pay and request

Resolve a recipient, review the amount and sign a direct MUSD transfer.

Borrow and save

Access Mezo Troves and the sMUSD Savings vault from the same wallet.

pocket.03 / PRODUCT WALKTHROUGH

One wallet. Four useful actions.

Pocket combines direct payments, merchant invoices, Mezo Borrow and Savings. The wallet signs each payment; the server independently verifies its receipt.

01 · Send / Request

Direct transfers and payment-request records support everyday payments.

02 · Borrow

Open, inspect, repay or close a BTC-backed Trove using protocol-specific calls.

03 · Save

Deposit MUSD, withdraw and claim Savings yield from the embedded wallet.

Wave 1 review release: merchant checkout, corrected Savings accounting and configured welcome campaign.03 / 08
pocket.04 / HOW IT WORKS

Wallet to wallet, verified on Mezo.

Pocket's payment path is direct. Postgres stores profiles, requests and activity; an internal ledger does not authorize or fund the current transfer flow.

User wallet

The Privy embedded wallet holds the MUSD and signs the ERC-20 transfer.

Mezo

Mezo executes the transfer. Native BTC pays gas; receiving requires no recipient transaction.

Pocket API

The server verifies transaction identity and outcome before recording payment activity.

Legacy vault settlement is isolated from direct payments.04 / 08
